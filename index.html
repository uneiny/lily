01 · PERSONAL PR

문제를 발견하고, 설명 가능한 형태로 정리합니다.

이 포트폴리오는 단순한 자기소개서가 아니라, QA 직무에서 바로 확인할 수 있는 산출물 중심의 PR 문서입니다. 경력 기술, 테스트케이스, 버그 리포트, 도구 활용 경험을 하나의 웹 포트폴리오 구조로 정리했습니다.

Career-to-QA Narrative

기존 업무에서 쌓은 품질 확인, 기록 관리, 고객 불편 분석 경험을 소프트웨어 테스트 관점으로 확장했습니다. 기능이 의도대로 동작하는지 확인하는 것뿐 아니라, 사용자가 실제로 어떤 지점에서 혼란을 겪는지 관찰하고 이를 재현 가능한 테스트 결과로 문서화하는 데 초점을 둡니다.

Core Positioning

신입 QA 지원자로서 강점은 화려한 개발 경력보다, 오류를 놓치지 않기 위한 꼼꼼한 확인 습관과 개발자가 재현할 수 있도록 현상을 구체화하는 문서화 능력입니다.

03 · TEST CASES

테스트케이스는 시나리오 기반으로 보여줍니다.

포트폴리오 예시는 채용공고 수집 웹 서비스 기준입니다. 단순 체크리스트가 아니라 사용 흐름, 필터 상태, 성능 체감까지 포함합니다.

TC ID Scenario Test Type Expected Result Status
JOB-COL-001 기본 선택 사이트 기준 채용공고 수집 실행 기능 / 정상 흐름 선택된 채용 사이트의 결과가 사이트별로 구분되어 표시된다. OPEN
JOB-FILTER-002 필터 해제 후 재설정 시 결과 정확성 확인 상태 전이 / 회귀 이전 필터 조건이 남지 않고 새 조건만 반영된다. FAIL
JOB-PERF-001 사이트별 수집량 50개 설정 후 대기시간 확인 성능 / 사용성 진행 상태가 표시되고, 사용자가 중단 여부를 판단할 수 있다. FAIL
JOB-UI-004 다른 사이트 선택 영역의 클릭 가능성 확인 UI / 사용성 마우스 오버 시 클릭 가능한 요소임을 명확히 인지할 수 있다. PASS
04 · BUG REPORTS

버그는 재현 가능해야 합니다.

Jira 등록을 전제로, 현상 설명보다 재현 조건·환경·기대 결과·실제 결과를 명확히 드러내는 구성을 사용합니다.

나라일터 채용공고 수집 실패 Major
BUG-JOB-001 · Collection

나라일터 선택 후 수집 실행 시 결과가 표시되지 않거나 누락됩니다. 핵심 수집 기능 신뢰도에 직접 영향을 주는 결함입니다.

잡알리오 채용공고 수집 실패 Major
BUG-JOB-002 · Collection

렌더링 이후 공고 데이터가 결과 목록에 반영되지 않습니다. 파서 로직 또는 네트워크 응답 처리 검토가 필요합니다.

수집량 증가 시 대기시간 과도 Medium
BUG-JOB-003 · Performance

사이트별 30개 이상 수집 시 대기 시간이 길고 진행 상태 확인이 어렵습니다. 진행률, 타임아웃, 부분 결과 표시 개선이 필요합니다.

필터 재설정 후 결과 불일치 Major
BUG-JOB-004 · Filter

필터 해제 후 다시 조건을 설정하면 이전 상태가 남아 정확하지 않은 결과가 표시됩니다. 상태 초기화 검증이 필요합니다.
